# Structured output: five-minute contract demo (#12)

**What this shows:** Foundry makes the prompt agent return a predictable JSON
shape. Python checks the result and adds the execution metadata. It is not yet
the documentation-analysis workflow (#13).

## Prepare

Use the existing shared project from [setup](../setup.md) and authenticate with
your team Azure CLI account. The CLI uses `AzureCliCredential`, not a credential
fallback chain, so it follows that sign-in.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[prompt,dev]"
```

## Configure once (creates an agent version)

This preserves the selected prompt agent's tools, approval rules, model and
reasoning settings. It appends assessment instructions and attaches the generated
`AnalysisOutput` schema through native `text.format`.

```powershell
.\.venv\Scripts\python.exe -m contracts.prompt `
  --project-endpoint <project-endpoint> `
  --agent-name <existing-prompt-agent> --agent-version <latest-version> --configure
```

Record the returned version. Do not configure again just to invoke the agent.
The command rejects an outdated base version and avoids creating a new version
when the schema and instructions already match. Explicit version selection
matters: callers using latest will observe the new structured response.

## Run the no-tools demo

Read the model version from the Azure deployment, not from the model response:

```powershell
az cognitiveservices account deployment show -g <resource-group> `
  -n <foundry-account> --deployment-name <chat-deployment> `
  --query properties.model.version -o tsv

.\.venv\Scripts\python.exe -m contracts.prompt `
  --project-endpoint <project-endpoint> `
  --agent-name <prompt-agent> --agent-version <configured-version> `
  --model-version <model-version> `
  --request .\src\contracts\examples\request-v1.json
```

The fictional request contains references but no source content. The model should
return `insufficient_information`, describe the missing sources and leave findings,
changes and evidence empty. The client rejects invented findings in this demo.

Tools are disabled with `tool_choice="none"`. Foundry may still list MCP tools;
discovery metadata is not a tool call. Actual tool calls, approval requests,
refusals and incomplete responses fail explicitly rather than becoming a result.
The invocation costs model tokens and may create Foundry response history;
it does not write to the wiki or change the agent definition.

## Explain the result

- **Analysis:** generated by the model, schema-constrained by Foundry and validated by Python.
- **Request ID:** copied from the caller's validated request.
- **Provenance:** agent/version/model read from Foundry, model version supplied
  from deployment configuration, actual instruction text hashed as the prompt version.
- **Human review required:** a flag, not an approval or an executed write.

For real findings, #13 must retrieve source content and verify the evidence.
The hosted v0 stub stays a separate demo; no Cosmos DB or additional CI pipeline
is introduced here.

## Gotchas and references

| Symptom | Explanation / fix |
|---|---|
| API rejects `agent`, `instructions` or `text` on invocation | Current API uses `agent_reference`; save instructions and schema on the agent version |
| MCP tool-list item precedes the JSON message | Accept discovery metadata, but reject actual tool calls in the no-tools demo |
| Schema-valid output has a nonexistent evidence ID | JSON Schema cannot check cross-array references; Pydantic rejects it |
